## 1. 사고에서 나온 규칙들

라이브 봇 코드의 절반은 신호가 아니라 사고 방어입니다. 아래는 실제로 겪은 일과 그 뒤에 생긴 규칙입니다.
모든 방어에는 그 사고를 재현하는 테스트가 붙어 있습니다.

| 사고 | 원인 | 지금의 규칙 |
|---|---|---|
| 백테스트와 실전이 1년에 4건 어긋남 | 같은 진입 규칙이 세 곳에 복사돼 있었고 한 곳만 고침 | **판정 규칙은 한 곳에만.** 화면용 복제는 매번 권위 값과 합계를 대조하고, 어긋나면 숫자를 고치지 않고 "어긋났다"고 표시 |
| 리플레이에서 이긴 거래 24건 증발 | 대조(자가치유)가 청산 확인보다 먼저 돌아 봇 자신의 청산을 지움 | tick 순서 고정: **청산 확인 → 대조** |
| 추세추종이 다른 전략의 $5,000로 BTC 매수 | 전략들이 "지갑 잔고 = 내 돈"으로 계산 | **몫 장부** — 전략은 자기 몫만 보고, 몫은 자기 체결로만 움직임. 실전은 서브계정 분리 |
| 검증 안 된 값으로 9일간 거래 | `.env` 한 줄이 빠져 코드 기본값으로 동작 | **fail-closed** — 값이 없거나 범위 밖이면 멈춤 |
| 보호 주문 없는 포지션 | 합계는 최소 주문 금액을 넘었지만 분할 조각이 못 넘어 손절 주문만 거부됨 | 들어가기 전에 조각 단위로 거절 |
| 손절·익절이 없는 것처럼 보임 | 조건부(Algo) 주문은 일반 주문 조회에 안 나오고, 트리거되면 다른 주문 ID로 체결 | 실제 체결 주문 ID 추적, 고아 조건부 주문 탐지 |
| 장부가 틀린 채 확정 | 데모 시장가 응답의 평균가가 0 | **모르는 값은 null.** 종결 응답이 비면 단건 조회·체결 내역으로 채움 |
| 대시보드 호스트가 죽음 | API 키가 없으면 DI 생성 중 예외 | 감시 화면은 **fail-visible** — 출처가 죽어도 뜨고 죽었다고 표시 |
| 인터넷 공개 화면의 위험 | 화면에 진입 멈춤·청산 버튼이 있었음 | 조작 경로 제거 + 구조 검사로 재도입 차단 |
| 정지 스위치 하나가 두 전략을 막음 | 눌림목용 "신규 진입 멈춤"이 추세추종 매수도 막음 | 전략별 봇·계정 분리 |

## 2. 두 언어 구현 대조

- 정답지는 파이썬이 생성한 `fixtures/*.json`. C# 테스트가 지표·진입안·사이징·백테스트 결과를 대조합니다.
- 결과: 7년 백테스트 **261거래 일치**, 델타 중립 체결 162건·181일 상대 오차 1e-9 이내.
- **파이썬이 정답은 아니다.** 어긋나면 자동으로 C#을 의심하지 않고, TA-Lib·거래소 문서 같은 외부 기준으로 3자 검증합니다.
  이 과정에서 찾은 파이썬 쪽 버그: 비표준 ATR, 자가치유 순서, 계층 이름 불일치, 2차 대기 만료 단위, MDD 고점 미기록, 일일 손실 한도 기준(초기 자본 vs 현재 자본).

## 3. 엔진의 정확성 규칙

- 트레일링 갱신은 그 봉의 청산 판정 **뒤** — 앞이면 미래를 보고 거래하는 셈
- 같은 봉에서 손절과 익절을 둘 다 스치면 **손절이 이긴다** (보수적 가정)
- 1차 익절 후 미체결 2차 진입은 취소 — 안 하면 평균가가 바뀌어 본전 손절선이 어긋남
- 워밍업 구간을 0으로 채우지 않음 (NaN), `ewm`은 `adjust=False`
- 손상된 데이터를 조용히 건너뛰지 않음 — 데이터가 조용히 줄면 백테스트가 조용히 거짓말함

## 4. 테스트 전략

| 종류 | 예 |
|---|---|
| 파이썬 대조 | 지표 하나하나, 진입안, 사이징, 전체 백테스트 거래 목록 |
| 라이브 사고 방어 | 재시작, 중복 체결, 응답 끊김, 결과 불명, 손절선 통과, 보호 주문 실패 |
| 구조 검사 | 프로젝트 참조 허용 목록, 계층별 금지 의존, 대시보드 주문 경로 금지 |
| 리플레이 | 과거 시세를 라이브 봇에 흘려 백테스트와 신호가 같은지 확인 |
| 돌연변이식 확인 | 새 방어를 일부러 되돌려 해당 테스트가 실제로 실패하는지 확인 |

CI(GitHub Actions)는 구조 검사와 시세 데이터 없이 도는 테스트 1,044건을 커밋마다 돌리고,
7년치 시세가 필요한 테스트는 배포 스크립트가 깨끗한 작업트리에서 전체로 돌립니다.

## 5. AI 에이전트와 함께 개발하기

509개 커밋 중 490개를 Claude Code와 Codex가 작성했습니다. 그만큼 **사람이 하는 일의 성격이 바뀌었습니다.**

- **기준을 먼저 쓴다.** 사전 등록 문서와 통과 조건은 AI가 결과를 보고 기준을 움직이지 못하게 하는 장치이기도 합니다.
- **구조를 테스트로 박는다.** AI는 급한 수정 한 줄로 경계를 쉽게 넘습니다. 아키텍처 테스트가 그걸 컴파일 직후에 잡습니다.
- **저장소에 맥락을 남긴다.** 결정과 그 이유(사용자 결정 날짜 포함), 거래소 문서에 없는 함정, 윈도우 환경 주의를 저장소 문서에 적어 다음 세션이 같은 실수를 반복하지 않게 합니다.
- **주석은 "왜"를 적는다.** 특히 사고에서 나온 규칙은 그 사고를 같이 적습니다. 사람도 AI도 그 코드를 함부로 지우지 않게 됩니다.
- **실전 돈과 관련된 결정은 사람이 한다.** 입금, dry-run 해제, 예약 작업 등록, 데이터 다운로드처럼 되돌리기 어렵거나 비용이 드는 단계는 명시적 승인을 거칩니다.

## 6. 거래소에서 실측한 함정 (문서에 없는 것)

- 조건부 주문은 일반 주문 조회에 나오지 않고, 트리거되면 다른 주문 ID로 체결된다
- 데모 시장가 응답의 평균가는 0이다
- 데모는 오래된 `startTime` 조회를 거부한다 — 되는 데까지 하루씩 줄여야 한다
- 최소 주문 금액은 분할 조각 기준으로 봐야 한다
- 어느 포지션에도 묶이지 않은 조건부 주문은 며칠 뒤 혼자 트리거되어 "봇 밖 청산"이 된다
- 윈도우 `.cmd` 파일은 순수 ASCII여야 한다 — cmd.exe가 코드페이지 949로 읽어 UTF-8 한글이 다음 줄의 명령을 삼킨다
